# 虚拟细胞扰动预测：E 组前期准备

**节点：2026 年 11 月 8 日**  
**任务：**整理 K562、CRISPRi 与通路分析背景；选定基因集；起草测试案例选择规则。

## 1. 项目问题

本项目使用人 K562 细胞的 CRISPRi Perturb-seq 数据，训练模型预测未见过的目标基因受到抑制后，细胞群体的平均基因表达变化。对于目标基因 \(g\)，真实响应定义为：

\[
\Delta_g = \bar{x}_{g} - \bar{x}_{\mathrm{control}}
\]

其中两项分别为目标扰动组和对应对照组的平均表达，表达空间与对照细胞划分由 B 确定。模型输出同一批输出基因上的预测变化。E 的工作是比较真实与预测的变化基因和通路，解释模型在哪些生物过程上捕捉到扰动响应。

## 2. 生物学背景

### 2.1 K562 与数据来源

K562 是源于人慢性髓性白血病的细胞系。Replogle 等在表达 dCas9-KRAB 的 K562 细胞中开展了两套 Perturb-seq 筛选：一套面向表达基因，另一套面向常见必需基因。本项目拟使用其中 K562 Essential 数据的公开分发版本；具体细胞数、基因数、扰动标签、对照标签和数据处理状态以 B 对实际文件的检查为准。原始研究结合单细胞 RNA 测序和 sgRNA 捕获，将细胞的扰动身份与转录表达联系起来。[1]

项目估计的是该数据条件下的**细胞群体平均响应**。K562 是肿瘤细胞系，所得解释应放在这一细胞背景、CRISPRi 干预方式以及对应采样时间内，不直接推广为其他细胞类型或个体的响应。[1]

### 2.2 CRISPRi 和 Perturb-seq

CRISPRi 利用向导 RNA 将失去切割活性的 dCas9 导向目标基因调控区域；与 KRAB 抑制结构域结合后，可降低目标基因的转录。它研究的是表达抑制后的响应，不等同于把目标基因从基因组中删除。[2] 在 Perturb-seq 中，细胞的 sgRNA 信息与单细胞转录组测量相连，可比较同一扰动组与非靶向对照组的表达。[1]

扰动目标本身的平均表达是否下降，可作为案例检查的一部分；但单个目标的观测还受到测量噪声、细胞数及抑制效率影响。目标基因若不在模型的输出基因列表中，应记为“未覆盖”，不能当作模型预测正确或错误。

### 2.3 为什么分析通路

模型一次预测约 2,000 个输出基因，逐个基因难以概括整体变化。通路富集分析检查变化较大的基因是否集中出现在已知生物过程或反应通路中，为解释预测提供更高层次的线索。这里采用**过度富集分析（ORA）**：从输出基因中选出一个变化基因集合，比较某通路在该集合中出现的比例与在背景基因中的比例。[3]

富集结果是对基因集合与通路注释重叠的统计描述；上调或下调基因富集到某通路，并不能单独证明该通路被激活或抑制，也不能单独证明因果机制。通路间常有共享基因，多个显著通路可能反映相近的生物过程。

### 3.2 真实与预测的统一分析方案

以下为供 11 月 12 日脚本实现和 D 联调的**初步参数**，正式测试前共同固定。注意：`docs/interfaces.md` v0.1 建议背景限定为有注释的基因；本草案建议包含共同输出基因中的未注释基因。两种口径目前尚未统一，须由 A、D、E 在查看测试结果前共同决定并同步更新接口。

1. **统一基因标识。** 以 B 输出的唯一人类基因符号及其映射表为准，将真实变化、模型预测与 Reactome GMT 对齐。记录重复符号、无法映射项和每个通路与输出基因的交集。出现一对多或多对一映射时请 B 确认统一处理，避免静默合并或擅自将符号转大写。
2. **统一背景。** 对每套划分，取 B 确定且真实值、各比较方法均可计算的共同输出基因作为背景集合；每个案例的真实值、Ridge 和平均扰动基线使用完全相同的背景。背景包含未被 Reactome 注释的输出基因；它们仍是可被选入变化基因列表的候选。与本次案例数据无关的全基因组基因不纳入背景。[3]
3. **统一变化列表。** 在共同背景内，分别对真实值、Ridge 和平均扰动基线按变化绝对值从大到小排序，取前 20 个基因。绝对值相同时按基因符号字典序升序处理；真实值与预测值各自排序，不用真实 Top-20 为预测挑选基因。若背景不足 20 个，标为无法按既定方案分析并记录原因。
4. **基因与方向。** 主分析使用上述各自的 Top-20 集合计算富集，另报告真实与预测 Top-20 的交集、重合率（交集数 / 20）和交集内方向一致比例。方向一致比例的分母为双方变化均非零的交集基因数；分母为零时记为不可计算。可补充对正变化和负变化基因分别做探索性富集，报告各自列表大小和完整检验结果；不要把零值算作上调或下调。
5. **通路筛选与检验。** 每个 Reactome 通路先与共同背景取交集，保留交集大小为 10–500 的通路。对每个列表与每个保留通路进行单侧超几何过度富集检验，完整纳入零重叠通路（其 p 值为 1）；分别对每个“案例 × 方法 × 基因列表”的全部保留通路使用 Benjamini–Hochberg 方法校正，报告 p 值、调整后 p 值、通路大小、重叠基因数及基因名。建议以调整后 p < 0.05 标记显著结果，同时保留完整表。
6. **比较与解释。** 并列展示真实和预测的通路重叠、效应方向相关的基因证据及调整后 p 值；也展示平均扰动基线的结果。真实显著而预测不显著本身不等于二者存在显著差异。Top-20 很短，可能没有显著通路；如无显著结果，照实报告并展示候选重叠，不将未校正结果写成显著发现。

输出表建议字段：`split_seed, target, method, list_type, pathway_id, pathway_name, background_n, list_n, pathway_n, overlap_n, overlap_genes, p_value, p_adj`。这里 `method` 可用 `truth`、`ridge`、`mean_baseline`；`list_type` 用 `top20_abs`、`top20_up`、`top20_down`。上下调列表从各自绝对值 Top-20 中拆分得到。

## 4. 测试案例选择规则（草案，待 D 确认）

### 4.1 目的与时间

在查看测试模型预测、逐目标误差、Top-20 重合率或通路结果**之前**，由 E 和 D 固定并保存规则，再选案例。避免只挑模型效果好或生物学故事容易解释的目标。11 月 12 日完成联调时与 D 确认；11 月 16 日固定最终版本。

### 4.2 抽取流程

1. **确定一套展示划分。** 主案例固定使用项目的 **划分种子 42**；三个种子的整体测试结果仍由 D 分别评估和汇总。不要将不同种子下重复抽中的目标当成独立生物学样本。
2. **建立候选清单。** 由 B 提供种子 42 的测试目标列表及每个目标的细胞数、目标符号、数据质量状态；D 根据预先约定的数据规则检查。纳入被分到测试集、符号能唯一对应、通过 B 质量控制且扰动细胞数不少于 20 的单基因目标；要求该划分有可用的对应对照。阈值与项目方案一致，若 B 正式数据规则修改，由 E、D 在查看测试表现前同步更新并记录。排除和原因写入清单。
3. **固定规则抽取 3 个。** 对每个候选目标，将字符串 `E-case-v1|42|` 与 B 提供的标准目标符号拼接，按 UTF-8 编码后计算 SHA-256。按哈希十六进制字符串升序排序，取前 3 个作为主案例；哈希相同时按目标符号的 Unicode 字典序升序。候选不足 3 个时全部保留并报告数量；不能为了凑数降低质量条件。
4. **登记并冻结。** 保存候选清单、排除原因、所有候选的哈希、选中次序、数据版本、划分文件和日期。冻结后再由 D 提供目标真实响应和评测结果。抽样不使用响应强度、细胞数排序、目标通路、模型误差或预测结果；细胞数只用于既定质量门槛。
5. **出现技术问题时。** 如果冻结后发现某个案例的必需数据不可用或文件损坏，保留其原记录和原因，按同一哈希排序选取下一位，形成替补记录；模型表现差、通路不显著或不便解释均不构成替换理由。

不依赖第三方库的抽样伪代码如下。`eligible_symbols` 必须是步骤 2 审核后的去重列表，输入的符号与输出名称保持一致：

```python
from hashlib import sha256

def order_cases(eligible_symbols):
    def key(symbol):
        digest = sha256(f"E-case-v1|42|{symbol}".encode("utf-8")).hexdigest()
        return digest, symbol

    return sorted(set(eligible_symbols), key=key)

selected_cases = order_cases(eligible_symbols)[:3]
```

### 4.3 每个案例的预定比较

- 一张表列出真实、Ridge 与平均扰动基线各自的 Top-20 基因及方向、交集和方向一致比例。
- 比较所有共同输出基因上的真实与预测变化散点、每目标误差及相对平均扰动基线的误差；指标由 D 的统一脚本计算。
- 查看目标基因本身的真实与预测变化；不在输出基因中则标记“未覆盖”。
- 对真实、Ridge 和平均扰动基线分别执行同参数 Reactome ORA，展示完整结果表及代表性通路。
- 基于通路注释和公开文献解释与目标相关的结果，区分“本项目中观察到的变化”和“文献中的已知功能”。

主案例按上述规则随机化式确定。之后如需解释总体中预测较好和较差的目标，可由 D 按预先写明的误差定义选取，作为**事后探索案例**单独标注，不替代主案例，也不据此代表整体性能。
