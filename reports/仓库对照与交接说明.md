# 仓库对照检查与 B 交接说明

检查仓库 https://github.com/stt456/virtual-cell-perturbation ，基于提交 df389de、统一接口 v0.1；仓库此前尚未接入真实 B 数据。结果在本机 D 盘生成，没有修改或上传远程仓库。

## 已完成的接口改进
`仓库接口交付_v0.1/data/processed/cell_metadata.csv` 使用仓库约定的 cell_id、target_gene、is_control、guide_id、batch，对照标签为 control。未知 guide 与 batch 留空。`expression.h5ad` 仅保留纳入的 162648 个细胞；X 使用原始分发版本 X，var 的索引为 Ensembl ID，gene_name 为符号。清除原文件 uns 及 var 中的上游统计字段，但不能撤销上游预选 5000 基因本身可能引入的泄漏。

`data/splits/seed_<seed>.json` 为仓库约定的目标与对照列表；`data/processed/seed_<seed>/output_genes.txt` 为去重的基因符号，`output_gene_mapping.csv` 保存符号到 Ensembl ID 映射。`aggregates.npz` 含 target_ids、gene_ids、split、mean_perturbed、mean_control、delta_true、n_cells，所有数组可以 allow_pickle=False 读取。对照按划分分别聚合，缺批次信息，暂未匹配批次，仅为供全组讨论的处理规则。metadata.json 记录数据、处理和限制。每套输出 2000 基因的符号均无重复；源 5000 基因存在 TBCE 重名，建模特征侧必须明确歧义基因映射策略。

各 seed 同时提供 C_train_val.npz 和 D_test.npz，便于避免将测试 delta 交给 C；原 aggregates.npz 是包含测试标签的完整文件，留给 D 或统一管理人。完整 expression.h5ad 和原始 h5ad 仍含测试细胞和表达，也不可作为盲测情况下的 C 无限制交付。C 的 PCA 只用训练对照且特征标准化仅用训练目标；应由 B/A 或 C 在约束访问的流程中先导出训练控制细胞和训练/验证所需数据。测试目标 ID 本身可用于产生预测，测试表达及 delta 应由 D 保管。

## 已核验
真实数据的 split 互不交叉，每个种子 1086 目标、10691 对照细胞；NPZ 均为 1086 × 2000，基因顺序与 output_genes.txt 一致、数值有限，delta 等于扰动均值减相应对照均值。上轮独立复算 18 个对照或扰动条件，误差小于 1.5e-6。详见 validation.json、原 results/aggregation_independent_checks.csv。仓库自带框架检查及五项单元测试通过，但这些测试只使用模拟数据，不等于真实数据质量已全部核实。

## 仍需协调
1. 本数据缺失 guide 和 batch 字段；无法开展真实批次匹配和分布统计。汇总按划分内对照池的算术平均处理，需与 A/C/D 决定是否接受。须追溯原始元数据才能补齐。
2. X 抽样呈非整数，但仅凭当前文件无法验证归一化与 log1p 的确切来源；全组应先确认表达空间，不要误称原始计数。上游 5000 基因的筛选范围未证实，严格无泄漏需要从原始全基因数据重新处理。
3. 目标可作为 PCA 基因表示的覆盖率并非 2000 输出基因覆盖率：目前保留目标 411/1086 的符号存在于上游 5000 基因集合，剩余目标按方案需要回退并分别报告。跨物种 ID、符号别名与重复符号可能影响精确匹配，需要 C 与 B 协商。
4. 不同种子的 2000 输出基因可不同，每个种子内方法必须共享同一顺序和基因集合，核对 output_genes.txt 和 NPZ 中 gene_ids。
5. 该仓库 Python 3.11/anndata >=0.10 等是未验证的起始依赖，现行处理环境是 Python 3.9/anndata 0.8；需在仓库环境中重新运行/验收，不能宣称兼容范围已验证。
6. 仓库 .gitignore 排除原数据、处理数据、划分和 NPZ；应通过协商的文件渠道交付数据，并在仓库提交代码和小型说明；不要把大数据或个人路径加入 Git。
